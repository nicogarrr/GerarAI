# ragas (Apache-2.0) para el crossover de metricas del harness RAG.
#
# NO lo usa el servicio ni la puerta de CI: los cuatro numeros gateables se
# calculan con evals/rag/rag_metrics.py (sin dependencias de terceros). Este
# fichero es el entorno AISLADO del crossover. Un solo comando, desde data-engine/:
#
#     bash scripts/ragas_crossover.sh
#
# (crea .venv-ragas con uv o, si no hay uv, con python3.12 -m venv + pip, instala
# esto y corre `scripts/run_rag_evals.py --dry-run --ragas-crossover`).
#
# POR QUE ESTAS VERSIONES (verificado instalando y ejecutando, 2026-10-27, py3.12):
#
# - La version anterior de este fichero era insatisfacible: fijaba
#   langchain==0.2.16 (langsmith<0.2) junto a langchain-core==1.3.3
#   (langsmith>=0.3.45). `pip/uv install -r` fallaba antes de instalar nada.
# - ragas 0.4.3 no pone techo a langchain-*, pero `ragas/llms/base.py` hace
#   `from langchain_community.chat_models.vertexai import ChatVertexAI`.
#   langchain-community 0.4.2+ ya no trae ese modulo -> ImportError en el
#   primer `import ragas.metrics`. 0.4.0 y 0.4.1 si lo traen y funcionan con
#   langchain-core 1.x, asi que se fija 0.4.1.
# - Las metricas NonLLM usan NonLLMStringSimilarity, que exige rapidfuzz
#   (ragas no lo declara): sin el, ImportError al instanciar la metrica.
# - El resto se fija a lo que el resolutor eligio en la instalacion verificada,
#   para que el crossover sea reproducible.
#
# Por que NO va en requirements.txt: langgraph (RAG y tesis) exige un
# langchain-core reciente y el pin de langchain-community de aqui no debe
# arrastrar al servicio. Venv aislado siempre.
